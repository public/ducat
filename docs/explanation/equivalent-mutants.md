# Equivalent mutants

The nightly mutation run (see [How ducat is tested](how-ducat-is-tested.md#mutation-testing)) leaves some mutants alive that no test can kill, because no input can tell them from the original code. Where every mutant of one kind on a line is like that, a `// Stryker disable next-line` comment at the site says why. This page lists the rest, file by file: mutants on lines where the tests kill other mutants of the same kind, so they show as "survived" in the report.

## rate.ts

| where                                       | mutants                                                                                                                                                         | why they are equivalent                                                                                                      |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `multiplyByRatioAtScale`'s number fast path | the guard and its scale-shift bounds as `true` or `false` or moved by one; the bounds on the scaled numerator and denominator as `true`, `false`, `<`, `>` or ` |                                                                                                                              | `; the product bound as `false`, `<`or`>`(only narrowing it: the product bound as`true`would let an inexact product through, and`test/rate-edges.test.ts`kills it); the shift branches as`true`or`>=`/`<=`; `-scaleShift`as`+` | A broken guard either takes the bigint path, which gives the same quotient, or computes with NaN (a missing power of ten), which fails the bound checks and falls back to it.
