# Equivalent mutants

The nightly mutation run (see [How ducat is tested](how-ducat-is-tested.md#mutation-testing)) leaves some mutants alive that no test can kill, because no input can tell them from the original code. Where every mutant of one kind on a line is like that, a `// Stryker disable next-line` comment at the site says why. This page lists the rest, file by file: mutants on lines where the tests kill other mutants of the same kind, so they show as "survived" in the report.

## money.ts

| where                                                                                                                                                                                               | mutants                                                                                                                                                                                                                                                   | why they are equivalent                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| number fast paths: `scaleUp`, `scaleDown`, `add`, `subtract`, `sum`, `multiply`, `multiplyByRatio`, `divide`, `money()` for safe integers, `majorPart`, `minorPart`, `hasFraction`, `toMinorNumber` | the guard as `false` or its block emptied; a bound `<= MAX_SAFE_MINOR` as `<`, or `>= -MAX_SAFE_MINOR` as `>`; `exponent <= 15` or `scale <= 15` as `< 15`; `sum`'s fast-loop conditions (the NaN marker, the type and scale checks) as `true` or `false` | Each of these only narrows the fast path, never widens it. The guard is a chain of `&&` checks; with one of them `false` (or its `typeof` string blanked, so the check can never hold), the chain fails and the call takes the bigint path. A bound moved from `<=` to `<` (or `>=` to `>`) changes the outcome for one input only, exactly ±(2^53 − 1), and sends it to the bigint path too. `< 15` sends scale 15 there. An emptied block falls through to the bigint path after it. In `sum`, every loop-condition change either leaves the fast loop earlier or skips it, and `add()` finishes the total. The bigint path computes the same exact value, and `normalizeMinor` makes it a number again when it is safe, so the result is identical. The mutants that would widen the fast path (the guard as `true`, a bound as `>` or ` |     | `) let an inexact float through. Those are killed by the ±2^53 tests in `test/money-edges.test.ts`. |
| `isValidScale`                                                                                                                                                                                      | the check as `false`; `<= MAX_SCALE` as `<`                                                                                                                                                                                                               | A scale that fails it goes to `checkScale`, which accepts the same scales and returns them unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `make`, `toBigInt`, `fromScaled`                                                                                                                                                                    | `typeof x === 'bigint'` as `true` or `false`                                                                                                                                                                                                              | `normalizeMinor` returns a safe number unchanged, and `BigInt()` of a bigint is that bigint.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `fromScaled`, `toScale`, `compare`, `equals`, `multiplyByRatio`, `toMinor`                                                                                                                          | a same-scale shortcut removed, or `<`/`>` on scales as `<=`/`>=`                                                                                                                                                                                          | At equal scales the general path multiplies or divides by 10^0 = 1 (or compares at that scale) and gives the same value.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
