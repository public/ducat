# Equivalent mutants

The nightly mutation run (see [How ducat is tested](how-ducat-is-tested.md#mutation-testing)) leaves some mutants alive that no test can kill, because no input can tell them from the original code. Where every mutant of one kind on a line is like that, a `// Stryker disable next-line` comment at the site says why. This page lists the rest, file by file: mutants on lines where the tests kill other mutants of the same kind, so they show as "survived" in the report.

| number fast paths: `scaleUp`, `scaleDown`, `add`, `subtract`, `sum`, `multiply`, `multiplyByRatio`, `divide`, `money()` for safe integers, `majorPart`, `minorPart`, `hasFraction`, `toMinorNumber` | the guard as `false` or its block emptied; a bound `<= MAX_SAFE_MINOR` as `<`, or `>= -MAX_SAFE_MINOR` as `>`; `exponent <= 15` or `scale <= 15` as `< 15`; `sum`'s fast-loop conditions (the NaN marker, the type and scale checks) as `true` or `false` | Each of these only narrows the fast path, never widens it. The guard is a chain of `&&` checks; with one of them `false` (or its `typeof` string blanked, so the check can never hold), the chain fails and the call takes the bigint path. A bound moved from `<=` to `<` (or `>=` to `>`) changes the outcome for one input only, exactly ±(2^53 − 1), and sends it to the bigint path too. `< 15` sends scale 15 there. An emptied block falls through to the bigint path after it. In `sum`, every loop-condition change either leaves the fast loop earlier or skips it, and `add()` finishes the total. The bound that matters, `- total` as `+ total`, is killed by the cases near 2^53 in `test/allocate-edges.test.ts`.                                                                                                                                                                                                                                                                                                                                                                  |
| `allocate`'s fast path, the float-quotient fix-up                              | both branches emptied or negated                                                                                                                                                         | `product + total <= 2^53 - 1` on this path, so `Math.floor(product / total)` is exact, by the argument for `divideAndRound` above.                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `allocate`'s selection loop (32 weights or fewer)                              | `ws[i] > 0` and `frac[i] >= 0` as `true` or loosened, `rem > 0` as `true` or `>= 0`, the 32 as 31 or no limit, the loop to `<= count`                                                    | The loop picks the largest remaining remainder, and that is always at least 1. The remainders add up to rem × total. Each is below total, and there are at most total buckets with a positive weight, so the top rem remainders are all positive. A zero-weight bucket (remainder 0) or a used one (-1) never wins. After a pick, the unpicked remainders still add up to more than their count, so the largest is at least 2. That is why a used bucket marked `+1` instead of `-1` can't win again either. The sort in `distribute` gives the same order. |

| `weightsScaled`                                                                | the bigint and safe-integer shortcuts                                                                                                                                                    | `parseDecimal` reads the same digits at scale 0. | `instalments`                                                                  | `scaledTotal.minor < 0` as `<= 0`; `* (neg ? -1n : 1n)` as `/`                                                                                                                           | Zero negated is zero, and x / ±1n is x × ±1n.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
